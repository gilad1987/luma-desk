## 4. Render loop / animation frame wiring

F, `loop` 2527–2549, first `requestAnimationFrame(loop)` at 3092:

1. `requestAnimationFrame(loop)` is the **first** statement (2528) — an exception later in the frame does not stop the loop.
2. Simulation and render: 2530–2534 (crowd uniforms, `songSync`, `autoTick`, `stepFades`, `computeOutput`, `updateVisuals`, `updateProps`, `animPerformers`, `controls.update`, composer or renderer, `drawOverlay`).
3. **Fast UI tick, every > 50 ms** (2536–2542): `updateExecUI()`, `updateEncUI()`, `updateAutoUI(now)`, `updateMaUI()` only if `deskMode === 'ma'`; then `#selInfo`, `#progInfo`, `#kHigh/#boBtn/#kFan .on`, `#bpmBox`, `#gmVal`, GM fader paint.
4. **Slow UI tick, every > 400 ms or when `uiDirty.all`** (2543–2548): `renderSeq()` if `sideTab==='seq'`, `renderSheet()` if `sideTab==='sheet'`, clear `uiDirty.all`, `#fps`, `#clock` (`toLocaleTimeString('en-GB')`).
   - Note: a dirty flag also resets `slowT`, and the fps counter is computed on that (shorter) window.
5. Other timers: `setInterval` 250 ms MA/Desk info (3069–3079); `setInterval` 500 ms REC timer (2908); toast timeout 1800 ms (694); `persist` debounce 500 ms (2309); grip `requestAnimationFrame(apply)` (3051); tour `requestAnimationFrame` per step (2871); `setView` animation rAF (890).

A, proposal: one `UiScheduler` owned by `main.ts`, called from the render loop after `drawOverlay` with `(t, now)`. Panels register `fast(now)` / `slow()` callbacks. `stateDirty` sets the dirty flag that forces the slow tick on the next frame (same as today: the next frame, not synchronously). `poolsChanged` re-renders `PoolsPanel` **synchronously** (today `renderPools()` is a direct call, never polled — 2544 does not include pools).

### 8.1 Keyboard — four listeners, order and phase are load-bearing

| # | Line | Target / phase | Behavior |
|---|---|---|---|
| K1 | 2259–2264 | `#cmd` `onkeydown` | Enter: push history (if non-blank) and `hi=-1`; bare `store` → `setStore(true)`, clear, **return without `preventDefault`**; else `runCmd`, clear, `preventDefault`. Escape: clear, blur, `setStore(false)`. ArrowUp/Down: history walk. |
| K2 | 2265–2273 | `document` bubble | Ignored when focus is INPUT/TEXTAREA/SELECT; ignored when guide open or `tIdx >= 0`; modal open → only Escape closes it; Space → `preventDefault` + GO+ on selected exec; Escape → `setStore(false)`; any single printable key without Ctrl/Meta → `cmd.focus()` (the key then types into `#cmd`). |
| K3 | 2887 | `document` **capture** | Escape: end tour if active; close guide if open. |
| K4 | 2911 | `document` **capture** | `f`/`F` without Ctrl/Meta, focus not INPUT/TEXTAREA, guide not open → `preventDefault` + `stopImmediatePropagation` + `toggleFs()`. |

Consequences (F, from the phases): K3 runs before K2, so Escape during the tour ends the tour, then K2 sees `tIdx = -1` and also runs `setStore(false)`. K4 stops K2, so `F` never focuses `#cmd`. K4 does not check SELECT, the modal or the tour (quirk Q5). Keep the capture flags on K3 and K4: capture listeners on `document` always run before bubble listeners, so the registration order of K2 relative to K3/K4 does not matter. K3 and K4 act on different keys (Escape vs F), so their relative order does not matter either; main.ts keeps the legacy order (K3, then K4).
